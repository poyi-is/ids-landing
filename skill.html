What this skill does

  • Composes UIs from documented IDS components and variant values.
  • Loads the canonical stylesheet so data-* attributes match real CSS.
  • Treats CONTEXT.md and ai/llms.txt as authoritative for tokens and APIs.
  • Avoids one-off styling and invented props or tokens.

What IDS is

Ionic Design System is a typed React library: variant props map to data-* DOM attributes. An external CSS file applies theming. Without that CSS, components use minimal fallbacks — always import the stylesheet for on-brand UI.

How agents should use IDS

  1. Read CONTEXT.md and ai/llms.txt.
  2. Install ionic-design-system and import the default theme CSS at entry.
  3. Compose with IDS primitives; prefer Container for layout.
  4. Map designs to documented enums only; do not invent variant strings.
  5. If undocumented, say unsupported or stay neutral — do not fabricate tokens.

Install

Command
npm install ionic-design-system

Peers: react, react-dom (>= 18). Optional: lucide-react for icons.

Required stylesheet

Import once at app entry, before rendering IDS components.

Published URL

Module
import "https://ionic-design-system.github.io/ids-landing/styles/default.css";
import { Button, Container, Text } from "ionic-design-system";

HTML

Link
<link rel="stylesheet" href="https://ionic-design-system.github.io/ids-landing/styles/default.css" />

Do not skip the stylesheet and compensate with ad-hoc utility CSS on IDS nodes — that drifts from system behavior.

Token and component rules

  • Variants are constrained enums — use only values in ai/llms.txt or typings.
  • Color / spacing follow CONTEXT.md semantic usage, not arbitrary palettes.
  • Typography: prefer Text over raw headings with custom classes for system UI.
  • Layout: prefer Container props over bespoke flex/grid utilities for structure.

Do / don't

Do

  • Import default CSS; mirror docs and CONTEXT.md.
  • Use flat props or dimensionValues as in llms.txt.
  • For Button, follow llms.txt prop names (intent, not legacy color examples).

Don't

  • Don't pile inline styles or utilities to mimic IDS unless explicitly requested.
  • Don't invent parallel tokens or undocumented components.
  • Don't clone IDS primitives — compose them.

Stay on-system

Canonical URLs
https://ionic-design-system.github.io/ids-landing/CONTEXT.md
https://ionic-design-system.github.io/ids-landing/ai/llms.txt

When unsure, read the component section in llms.txt — do not guess enums.

Example prompt

Agent instruction
Build a settings panel in React using ionic-design-system. Import the published default stylesheet from ionic-design-system.github.io/ids-landing. Use only components and props from ai/llms.txt. Layout with Container; actions with Button (intent, appearance, size per docs). No custom hex — IDS intents and surfaces only.

Example React usage

tsx
import "https://ionic-design-system.github.io/ids-landing/styles/default.css";
import {
  Button,
  Container,
  Text,
  Input,
} from "ionic-design-system";

export function SignInPreview() {
  return (
    <Container display="flex" direction="column" spacing="md" padding="lg">
      <Text text="Sign in" tag="h1" size="2xl" weight="bold" />
      <Input type="email" placeholder="you@example.com" size="default" />
      <Container display="flex" direction="row" spacing="sm">
        <Button label="Continue" intent="primary" appearance="solid" size="md" />
        <Button label="Cancel" intent="neutral" appearance="ghost" size="md" />
      </Container>
    </Container>
  );
}

Guardrails

  • Never invent component names, export paths, or variant values.
  • Never replace the IDS stylesheet with an ad-hoc subset without a documented pipeline reason.
  • If the upstream ids repo publishes its own SKILL.md, tooling may prefer that link; this page tracks the landing copy and published CSS URLs.
